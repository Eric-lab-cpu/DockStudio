## 2. 工作方式(重要)

1. **先对齐范围**:读完文件后,用简要清单向用户确认 v2.0 实际圈定范围。默认建议范围(路线图 §6.3):
   - 核心圈定:#15 VS 规模吞吐、#16 ROC/AUC 富集度验证、#17 交互式 HTML 总报告、#18 数据打包导出、#20 跨平台安装 + headless CLI、#23 CITATION.cff/DOI。
   - 前置补丁(属 v1.2/v1.3,但若用户同意可并入 v2.0):#1 对称性感知 RMSD、#2 SMILES/CSV 配体输入、#13 多核任务池。
   - 是否引入 Fpocket / gnina 等第三方可执行(路线图 §7)必须先经用户同意,否则跳过。
   - 让用户勾选后,把最终范围写成本轮任务清单再动手。
2. **保持既有约定**:
   - core/ 下任何模块**不得 import tkinter/ttkbootstrap**(可无头测试);
   - GUI 中文;科学产物/脚本(如 `.pml`)保持 ASCII;
   - **绝不捏造数据**:所有数值来自真实运行;失败如实报告并给修复建议;报告只列真实执行的步骤;新增“实验性/探索性”能力必须在报告与 GUI 中显式标注;
   - 新 `RunConfig` 开关**一律默认 False**(旧工程向后兼容);
   - 既有输出文件名与目录结构不破坏(新增目录/文件可加,不重排旧的)。
3. **逐步增量**:每个特性独立成 commit;每步跑 `python -m compileall -q dockstudio tests` + 相关单测;不要一次性大改不验证。
4. 沙箱若没有 tkinter/GUI 依赖,请用「语法编译 + 无头端到端 smoke + 代码审查」验证 GUI,并在交付说明里如实写“GUI 未在 Windows 实跑,需用户在本机验证”。

## 3. v2.0.0 范围(按 §2 确认后的最终版填写此处)

> 建议执行者把确认后的清单展开为任务列表(每项含:目标、验收、涉及模块、测试)。

### 3.1 严谨性(核心)
- **对称性感知 RMSD**:自对接与准确性报告从“同元素贪心最近邻”升级为对称等价类感知的 RMSD;保留原贪心值作对比列;报告注明方法与对称性来源;单测覆盖对称配体(如含 PO4/羧酸/对称芳香)的合成案例,证明不误报 FAIL。
- **ROC/AUC 富集度验证工作流**:GUI 可选启用“验证模式”:用户导入已知活性 + 诱饵(decoy)两组 SMILES/SDF;引擎跑 VS 后输出 ROC 曲线图、AUC、EF1%/5%,写入结果目录并进报告;**无活性/诱饵数据绝不自动生成**;报告写明方法学与数据来源;AUC 为真实计算值。
- 多打分函数共识(Vinardo/smina)**可选加**:若用户同意引入,以“重打分=并列对比、不做加权平均混成一个数”为纪律;报告每次注明函数与引擎。

### 3.2 高通量
- **VS 规模吞吐**:支持数千–十万级配体;两段式(低 exh 初筛→Top-N 精修→Top-K);分批 + 流式写结果;进程池多核;按配体断点续跑;内存安全;运行摘要统计(总数/成功/失败/耗时/吞吐)。
- **headless CLI**:`python -m dockstudio run <project.json> [--out …]` 作为逃生门,复用 GUI 生成的工程文件;GUI-only 定位不变。

### 3.3 交互与报告
- **交互式 HTML 3D 查看器**:每个 Top 复合物导出自包含 HTML(3Dmol.js 或 NGL,离线可用),含口袋残基、相互作用线;结果页一键打开。
- **交互式 HTML 总报告**:目录 + Top-K 表 + 图 + 链接到各复合物查看器 + 方法/QC/环境;作为 md 报告的姊妹件。
- **数据打包导出**:一键生成 `.zip`(全部源文件:PDBQT/complex/report/CSV/JSON/HTML/环境 json),文件名含版本与时间。
- 可选 PDF 报告导出(若用户要):中文与图片正确嵌入。

### 3.4 生态与分发
- **跨平台安装**:Windows 保持 NSIS;新增 macOS/Linux 构建说明与脚本(引擎后端已跨平台);CI 脚本把三平台产物+MD5+Release 说明串起来。
- **CITATION.cff + Zenodo DOI 准备**:仓库根加 CITATION.cff;README 增加“如何在论文引用 DockStudio”;是否注册 DOI 由用户执行。
- **诊断中心(可选)**:常见错误目录→可读建议;把 v1.0 时代踩过的坑固化为帮助文本。

### 3.5 不做的(除非用户坚持)
- 不做自研 MM-PBSA/共价对接的黑箱内置(改为“导出供外部旗舰工具续算”的互操作)。
- 不默认捆绑 gnina/DiffDock;仅当用户确认且按外部可执行方式接入。

## 4. 工程实现要点(执行者参考)

- **数据模型**:`RunConfig` 增加新开关与验证模式配置;新增工程文件 `.dsproj`(JSON,向前兼容读旧 `config.json`);`models.py` 保持 dataclass + to/from_dict。
- **pipeline**:把“验证/富集度”作为可选阶段插入 ranking 之后、report 之前;任务队列化可先在 `batch.py` 内做,不急着重构 pipeline 全局。
- **新增模块建议**:`core/enrich.py`(AUC/EF/ROC)、`core/vizhtml.py`(HTML 查看器与总报告)、`core/project.py`(工程保存/打开/打包)、`core/parallel.py`(进程池/断点粒度)、`core/rescore.py`(若做多打分)。命名可与架构文档保持一致的风格。
- **依赖**:任何新依赖都需同步 `packaging/requirements-pip.txt`、`packaging/environment.yml`、`setup_env.bat`,并评估安装包体积;纯 Python/纯 pip 优先。
- **报告诚实性**:新能力一律进方法报告;标注“实验性”的能力要给一句“这意味着什么、建议怎么做”;不把重打分/CNN 数值当实验亲和力。

## 5. 验收标准(全部满足才算完成)

1. `python -m compileall -q dockstudio tests` 通过。
2. `python -m pytest tests -q` 通过;每个新特性有对应单测(含对称 RMSD 合成案例、AUC 用已知小数据集的确定性测试)。
3. 无头端到端 smoke 至少两种配置各跑通:旧配置(全部新开关关)与新模式(开关开);对比旧版输出兼容。
4. `_version.py` 更新为 `2.0.0`;GUI About/帮助、README 特性表、用户手册同步。
5. 写 `docs/定版记录_v2.0.0.md`:变更摘要、诚实已知说明、测试记录、安装包 MD5。
6. 重建 Windows 安装包并给出 MD5;若用户要,产出 Linux 产物与构建脚本;git commit 分特性提交,push + tag `v2.0.0` + GitHub Release(参考 v1.1 发布链路:https://github.com/Eric-lab-cpu/DockStudio )。
7. 最后给用户一份交付摘要:改了什么、验证了什么、哪里没在 Windows 实测、建议用户回归清单。

## 7. 给你的最后提醒

DockStudio 的差异化是「可发表级 + 诚实披露 + 一键免安装」。升级时,**宁可少做一个花哨功能,也不要破坏“报告只写真实发生的事”这条底线**。任何阈值、打分、RMSD、AUC 都必须是真实计算的,并在报告中留下版本与参数痕迹。
