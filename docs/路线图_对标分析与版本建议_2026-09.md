## 0. TL;DR(先看结论)

DockStudio 的差异化定位是**「可发表级、诚实披露、一键免安装」的批量对接平台**,这比 PyRx 等通用 GUI 严谨得多,但对照商业旗舰在**打分函数多样性、口袋发现、蛋白柔性、交互式可视化、VS 规模、并行与跨平台**六方面存在明显差距。建议按三条时间线推进:

- **v1.2(查漏补缺)**:对称性感知 RMSD、SMILES/CSV 配体输入、交互式 HTML 3D 导出、`.dsproj` 工程保存、口袋保守水开关、逐配体进度与 PDF 报告。
- **v1.3(科学升级 + 口袋发现)**:空腔/口袋检测(支持 apo 受体)、多构象 ensemble 对接、可旋转侧链柔性对接、多打分函数共识/重打分、自对接批量校准、多核任务池。
- **v2.0(旗舰对标,主题式大版本)**:以「**桌面级可发表虚拟筛选工作台**」为定位——数千到十万级配体吞吐、ROC/AUC 富集度验证工作流、可选 ML/CNN 重打分、交互式总报告、跨平台安装包与 headless CLI、诊断中心与 citation。

排序原则:P0 = 严谨性收益 / 实现成本比最高,且不破坏协议主流程;所有科学增强都以**可关闭开关**与**如实披露**方式加入,默认行为保持不变。

## 3. 对标对象清单(为什么选它们)

**A 组:免费 / 同类型一栈式 GUI(直接竞争,决定“用户不会流失给谁”)**

| 工具 | 定位 | 选作对标理由 |
| --- | --- | --- |
| **PyRx**(v1.2 已发布 ✅) | 开源桌面虚拟筛选 GUI,封装 Vina/AutoDock4 + Open Babel | 与 DockStudio 定位最接近(桌面、免费、VS);其界面/工作流是用户默认预期 |
| **CB-Dock2** ✅ | 网页版盲对接,**空腔检测 + Vina + 可选 FitDock 模板精修** | “无共晶配体也能自动找口袋”是高频需求,DockStudio 目前会报错 |
| **AutoDockTools / ADFR suite** ◎ | 官方 GUI 生态 | 体现官方对准备/排错/可视化交互的处理方式 |
| **PyMOL / ChimeraX**(open)◎ | 分子查看 | 用户拿到结果后下一步就是交互查看;决定可视化导出形态 |

**B 组:商业旗舰(功能天花板,决定“3 年后 DockStudio 长什么样”)**

| 工具 | 定位 | 可借鉴的具体能力 |
| --- | --- | --- |
| **Schrödinger Maestro / Glide** ✅ | 行业标杆;Glide SP/XP、IFD(-MD)、QPLD、CovDock、FEP+ | 打分函数分层(SP/XP)、诱导契合、共价、MM-GBSA、WaterMap、交互式项目 |
| **CCDC GOLD / Hermes** ✅ | 遗传算法对接;ChemPLP 等 4 打分;**显式水/约束/共价**;GA 设置透明 | 约束打分、水分子参与、多打分并列比较、口袋内原子处理 |
| **MOE(CCG)** ✅ | 旗舰桌面环境;Dock、药效团、MM 可视化 | 交互式 2D/3D 分析、SAR、脚本化(SVL);“能看到的”都是立体的 |
| **OpenEye(OEDocking FRED/HYBRID, ROCS)** ◎ | 刚性穷举+柔性 Hybrid;**ROCS 形状相似**;VS 富集度工具成熟 | 穷举式 VS、ROC/AUC 工作流、构象库 |
| **BIOVIA Discovery Studio(CDOCKER/LibDock)** ◎ | 制药公司常用 | CHARMm 力场对接、protocol 化流程 |

**C 组:计分/引擎与新一代方法生态(决定“科学上要不要跟进”)**

- **AutoDock Vina 1.2.x + Meeko** ✅:当前主引擎;官方版只内建 Vina 打分。
- **smina / Vinardo / AD4 打分** ✅:Vina 生态的替代打分(经验势),smina 可自定义。
- **gnina** ✅:基于 smina 的 CNN 打分/对接(需 GPU),是开源界“打分提升”的代表。
- **DiffDock / Uni-Mol+ / Chai 等生成式对接** ◎(2024–2026 活跃,⚠ 演进快):端到端生成姿态;作为“是否引入 ML 分支”的远期信号。

> 对标结论:不追求复刻 Glide/GOLD 的闭源打分与 FEP;务实目标是把 **Vina 生态能给的**:多打分、口袋检测、柔性残基、CNN 重打分,以及**旗舰级的交互、报告、工程体验**,用可发表级纪律整合进来。

## 5. 按四个方向的机会解读

### 5.1 科学严谨性增强

- **对称性感知 RMSD**(最高性价比):当前回贴/准确性用“同元素贪心最近邻、无对称修正”,对含等价原子(如 PO4、羧酸、对称苯环)的配体会**系统性高估 RMSD、误报 FAIL**。引入对称自动感知(参考 sPyRMSD 思路,或用 RDKit 等价类做重排)可让自对接判定更公平,是“发表级”的关键补丁。涉及 `selfdock.py`、`accuracy.py`、报告披露。
- **多打分共识/重打分**:单一 Vina 亲和力排序噪声大。可插拔 Vinardo / smina 自定义打分 / 后续 gnina CNN,对 Top-K 做“共识 + 离群标注”。关键纪律:**每次重打分都要在报告里写明用什么函数、训不训练、阈值来源**,绝不把不同打分混成一个数。
- **VS 富集度/ROC 验证**(v2.0 旗舰项):当用户提供“已知活性 + 诱饵(decoy)”时,自动算 AUC/EF(富集因子),量化“这个体系下 DockStudio 排序靠不靠谱”。这是发文章时审稿人最认的证据,也是 CB-Dock/PyRx 都不太做、能成为亮点的功能。
- **自对接批量校准/准确度档案**:多个已知共晶体系跑回贴,输出“该用户设置下 mode-1 成功率与 RMSD 分布”,给用户一把判断本次运行可信度的尺子。
- **保留的诚实边界**:质子化不冒充 pKa;盒内水/离子处理继续披露;ML 打分只做排序建议不做绝对亲和力;任何新增“黑箱”都标注局限。这些是产品口碑红线,不能为追平旗舰而破。

### 5.2 专业功能对标(挑 Vina 生态能给的)

- **空腔/口袋检测**:CB-Dock2 证明了“盲对接找口袋”是刚需。DockStudio 现策略是“无共晶就要求人工”,虽然科学上最稳,但用户经常只有 apo 结构。可选方案:Fpocket(C,成熟)或纯 Python 几何近似(如聚类疏水/可及表面凹陷)。**披露策略**:检测结果默认“候选口袋(探索性)”,命中仍需人工确认,报告中标注;绝不静默当真实位点。
- **多构象 ensemble 对接**:同一受体多个构象(不同晶体状态 / MD 帧)→ 各构象对接取最低或聚类,近似诱导契合且完全在 Vina 能力内;成本中等,收益大。
- **可旋转侧链柔性**:Vina 支持 `--flex`(受体侧链作为柔性残基)。做成 GUI 选项“口袋残基侧链柔性(实验性)”,对接后披露柔性残基清单。
- **显式水/保守水**:Vina 可将保留的晶体水当作受体刚性一部分参与空间位阻/氢键。做“保留口袋内水(实验性,默认关)”,并在方法报告中列清单。
- **共价 / MM-PBSA / WaterMap**:这些是 GOLD/Glide 的招牌,但**在 Vina 生态里没有等价且可靠的开源实现**。建议:共价与 MM-PBSA 放在 v2.0 之后,做成“导出供外部专业软件继续算”的互操作(导出复合物+打分+脚本),而不是假装内置;这样既不夸口,又让需要旗舰级后续的用户有出路。

### 5.3 易用与交互体验

- **交互式 3D 查看(低成本高感知)**:不必嵌 PyMOL。每个 Top 复合物导出一个**自包含 HTML(3Dmol.js / NGL)**,含口袋残基、相互作用线、测量;用户双击即在浏览器转/缩放。这是 Maestro/Hermes 给用户的最大体感,而实现几乎零依赖。
- **SMILES / CSV 配体输入**:生物学家常只有 SMILES 表。RDKit ETKDG 生成 3D + 去重 + 属性表,打通“清单→对接”。
- **`.dsproj` 工程文件**:目前 `config.json` + `pipeline_state.json` 已能续跑,但缺“项目保存/打开/最近列表”。加一层工程封装,结果页可重新打开,跨会话无痛。
- **运行反馈**:逐配体进度条/ETA/失败原因分类;运行结束摘要(多少成功/失败/跳过,各阶段耗时)。
- **一键 PDF 报告**(含图、表、方法、QC、目录树),对标“给导师/审稿人看”的场景。
- **模板预设**:快速探索 / 标准(发表级) / 高精度三档参数组,减少误设。
- **结果解释引导**:对 Top-K 差异<0.1 kcal/mol、自对接 FAIL、无共晶等给出“这意味着什么、建议怎么做”。

### 5.4 高通量与生态分发

- **多核任务池**:现在 `cpu` 参数 + 批处理应升级为进程池 + 队列 + 内存安全 + 按配体断点,支持数千配体不崩。
- **GPU 可选后端**:Vina-GPU / gnina 作为可选加速(不默认依赖),报告记录实际引擎版本。
- **跨平台安装包**:引擎本身 Linux/mac 用 python-vina/CLI 可行;缺的是 **macOS/Linux 安装产物**(AppImage/.dmg/conda 包)与 CI。这是“生态分发”里投入产出比很高的一项。
- **headless CLI**:虽然“仅 GUI”,但为集群/服务器加一个 `dockstudio run <project.json>` 逃生门(读取与 GUI 相同的工程文件),能显著扩大科研用途。
- **引用与版本归档**:`CITATION.cff`、GitHub Release 资产、可选 Zenodo DOI;让用户能在论文里稳定引用 DockStudio(尤其我们强调可发表级)。
- **教程与样例库**:内置更多真实体系样例(带共晶、apo、多受体、大库),降低上手门槛。

## 6. 版本路线图建议

### 6.0 通用原则

- 每次发布:**向后兼容**(新开关默认关 / 默认与原行为一致)、跑通 `compileall + pytest + 无头 smoke`、写 `定版记录`、Windows 安装包 + MD5、git tag/Release。
- 新科学特性全部走“**默认关闭 + 报告披露 + 参数留痕**”,不改变既有输出文件名与格式(除受控改名,如 v1.1 的 final_top{K})。
- 复杂度定义:小 ≤0.5 人周;中 ≤1.5 人周;大 ≥2 人周。

## 7. 关键风险与待拍板事项

1. **第三方可执行引入(需你拍板)**:
   - Fpocket(空腔检测):成熟的开源 C 工具(具体许可证与再分发条款需以官方为准),引入 C 可执行会增加打包与维护成本;替代=纯 Python 几何近似(精度低、零依赖)。二选一或先近似后 Fpocket。
   - gnina(CNN 重打分):大体积、GPU 依赖、模型许可需确认,建议“外部可选、不默认捆绑”。
2. **科学边界红线**:质子化、水、ML 打分、空腔候选都只做“披露式建议”,不做“黑箱结论”;ROC/AUC 只在用户给 active/decoy 时启用,不许自造活性数据。
3. **许可合规**:打包前复核 Vina/Meeko/RDKit/gemmi/PLIP/PyMOL-open-source/Fpocket/gnina 等的再分发条款(学术一般无碍,商业发行需自查;以 `THIRD_PARTY_NOTICES.md` 为基准持续更新)。
4. **维护成本**:单开发者长期维护 + 安装包体积 + 首次装配体验是大头;跨平台与 CI 会占用持续精力,建议分批上而不是全押 v2.0。
5. **基准数据版权**:若做 ROC/校准演示,使用公开 benchmark(如 DUD-E/DUD-A)需遵守数据许可并在文档标注。
